# Domain Docs

## Before exploring

- Read `GLOSSARY.md` at the repo root, or `GLOSSARY-MAP.md` if the repo later adopts multiple contexts.
- Read relevant decisions in `docs/adr/`.
- If these files do not exist, proceed without flagging their absence or creating them upfront.

## Use the glossary

Use domain terms as defined in the glossary. If a needed concept is missing, note the gap for domain modeling.

## Flag ADR conflicts

If a proposal conflicts with an ADR, name the ADR and explain why it may be worth revisiting.
